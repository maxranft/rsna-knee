RSNA KNEE: SCRIPTS TO RUN AND THEIR OUTCOMES
Last updated 2026-09-29. Run from the repo root with the project venv: .venv/bin/python <script>.
Every training run is also logged as one row in experiments.md. The results viewer is notebooks/results.ipynb.
Metric reminder: gold macro AUC (58 studies) decides. Gold differences below ~0.02 are noise.
Report macro AUC (4,349 studies) is the steadier signal for choosing between models.

ONE TRAINING AT A TIME on the Mac. Two in parallel filled swap on 2026-09-29 and both stalled (10+ min per epoch).
Chain runs:  while kill -0 <pid>; do sleep 15; done; <next command>
Pause / resume a run without losing it:  kill -STOP <pid>; pkill -STOP -P <pid>   (then -CONT to resume)

How to read an outcome, and what to do next:
  - Seed noise first: one seed per config moves report macro by ~0.004 and gold by ~0.010. A single-seed difference
    below that is not a result. Confirm a promising change with a second seed, or compare seed means.
  - Report macro up by >= ~0.005, with a bootstrap 90% interval above 0 and gold not down by more than 0.02:
      adopt the change and make it the new reference.
  - Report macro flat (interval straddles 0): keep the change only if it is cheaper (e.g. E1: 3x smaller, 2x faster).
  - Report macro down: reject. Keep the flag in the code, off by default.
  - Left/right check (scripts/side_split.py): the one-sided findings (menisci, tibiofemoral OA, MCL, Baker's) should
    score the same on left and right knees. E2 did not fix the MCL gap; the untested fix is a pixel-level flip of
    left knees before the encoder (a new feature cache on Kaggle, ~15 min T4).

Compare any two runs (per-label table + paired bootstrap):
  .venv/bin/python scripts/compare_runs.py runs/<reference> runs/<candidate>
  -> prints per-label gold/report AUC and, per metric, "diff, lo 5%, hi 95%, P(better)". ~10 s idle, minutes if busy.
Left-vs-right knee check:
  .venv/bin/python scripts/side_split.py runs/<id>
  -> report AUC per label for right and left knees, and the mean L - R gap for medial/lateral vs other labels.

2. LOCAL DATA PREP (Mac)
------------------------
scripts/fetch_features.py maxranft/rsna-knee-features-dinov2s-parts data/features/dinov2s
  Downloads the feature cache in ~200 MB parts (retries, resumable) and reassembles one .npy per shard.
  Outcome (2026-09-29): all 3 shards complete. 4,407 studies, 507,464 slices, 17 tokens x 384 dims, 6.6 GB.
  Re-running skips finished shards. The Kaggle API sometimes returns 429 (rate limit), so re-run it.

scripts/pca_cache.py data/features/dinov2s data/features/dinov2s-pca128 --k 128
  Projects every token onto its top-128 principal components and saves pca.npz for the submission.
  Outcome: 92.0% of variance kept (64 -> 84%, 192 -> 96%). 2.2 GB instead of 6.6 GB. ~1 min.

scripts/laterality.py --feats data/features/dinov2s
  Knee side (L/R) for every study -> meta/laterality.csv (tag, report, p_left, side, side_source, t1_plane).
  The classifier trains on the DICOM tag. It sees only mirror-antisymmetric image features.
  Outcome: the image probe matches the DICOM tag 99.2% out-of-fold (AUC 0.993). The report's side matches the tag
  only 96.9%, so the report is the noisier source. Final sides: tag 2,176, image probe 2,231. R 2,332 / L 2,075.
  ~1.5 min. Needs data/pp-slots/slots_shard{0,1,2}.csv (preprocess kernel outputs, fetched 2026-09-29).

scripts/make_folds.py
  Fixed 5-fold split -> meta/folds.csv. Committed. NEVER regenerate: every result depends on these folds.

scripts/review.py  [--demo]
  Local browser review tool (http://127.0.0.1:8765): grade predictions per study and finding -> meta/reviews.csv.
  For Max only. It shows images and report text, so never run it inside a Claude session.
